### Design consequences
1. **State refresh on `Stop` must be synchronous and fast** (target <150 ms: stdin payload + `git diff --stat` + a file write). Heavy work goes to a detached child (`nohup … &`), not `async: true`, because headless bench runs would lose it.
2. **Handoff discoverability is a feature, not luck:** the project `AGENTS.md` gets one line, "If `.vault/STATE.md` is newer than your session, read it and `.vault/INVARIANTS.md` first." Then even a literal `/resume`, or a model that ignores commands, lands on the packet. In OpenCode.app, `/resume` expansion is still to be confirmed [T].
3. **The `PostCompact` audit is confirmed buildable:** `compact_summary` is real text we can diff against `INVARIANTS.md`.
4. **The decay benchmark must use long sessions:** two turns compact without loss. Plant rules early, pad with realistic tool output to around 100k+ tokens, then compact, as in the paper's design.

### Consequences
1. **`/resume` now uses `` !`cat .vault/STATE.md` `` and `` !`cat .vault/INVARIANTS.md` ``** (updated in `spike-repo/.opencode/commands/resume.md`). That works through the server whatever the client does.
2. **Async `Stop` is allowed in real use;** keep the work under 150 ms anyway so headless bench runs behave the same.
3. **Ordering matters:** `SessionStart(compact)` runs *before* `PostCompact`, so the decay audit can't change what was injected in that same compaction. Re-injection must not depend on the audit, and it doesn't: invariants come from the rules file. The audit only logs and scores.
4. **D4 is the headline lesson for the README:** pinning guarantees *presence*, not *obedience*. For invariants that can be checked by machine ("never touch `/prod`", "never run `docker`"), Cortex should also emit a **`PreToolUse` deny rule**, which is deterministic and blocks the action. Prose rules are for everything else, and the bench must report obedience per model.
5. **The workspace `CLAUDE.md` loads in every project under `Claude Projects/`.** Keep it tiny; it is part of every project's prefix.
