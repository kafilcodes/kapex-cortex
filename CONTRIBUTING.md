# Contributing to Kapex Cortex

Thanks for helping. Cortex is small on purpose: every change has to keep it fast, dependency-free and safe to run in every chat.

## Set up

```bash
git clone https://github.com/kafilcodes/kapex-cortex.git
cd kapex-cortex
npm ci --ignore-scripts
npm run check
```

You need Node.js 23.6 or newer (Cortex runs TypeScript with Node's type stripping, no build step for the CLI).

## The rules every change keeps

- **Zero runtime dependencies.** Node built-ins only (`node:fs`, `node:crypto`, `node:sqlite`). Dev tools (TypeScript, esbuild) are fine.
- **Hooks never break the harness.** They always exit 0 and log errors to `.vault/private/errors.log`.
- **The Stop hook stays under 60 ms at p95.** `npm test` measures it on your machine.
- **Nothing is injected into normal chats** by default. The one standing cost is the deferred `open_panel` tool's name, about 85 tokens a message (measured 2026-11-27); don't add to it.
- **Every source file stays under 300 lines.**
- **Tests never read your real `~/.claude` or `~/.cortex`** (`test/helpers.ts` points both at temp folders).
- **A memory check never changes a file until the user presses Apply**, and every Apply can be undone.

## How the code is laid out

| Folder | What lives there |
|---|---|
| `src/core/` | the engine: handoff packet (`state.ts`), mission contract (`mission.ts`), transcripts, Memory check (`dream*.ts`), status |
| `src/hooks/` | Claude Code and OpenCode hook handlers |
| `claude-plugin/hooks/` | the panel and status strip (a Claude Code mod, `.tsx`) |
| `claude-plugin/cortex/` | generated by `npm run bundle`: never edit it by hand |
| `test/` | core tests (`node --test`) |
| `claude-plugin/tests/` | panel tests (`claude plugin test claude-plugin`) |
| `scripts/` | bundling, the benchmark, the 5-hop telephone, previews |

Edit `src/`, then run `npm run bundle` so the plugin's copy and its pre-built `hook.mjs` match. `npm run check` fails if you forget.

## Before you open a pull request

```bash
npm run check                          # type check, bundle up to date, core tests
claude plugin test claude-plugin       # panel tests (needs Claude Code)
node scripts/benchmark.ts              # Memory check 6/6, 0 false positives; handoff 10/10; telephone 13/13
```

Add a test for every bug you fix: the test should fail without your fix. Describe in the pull request what you measured, and keep measured numbers apart from estimates.

## Reporting bugs

Open an issue with what you did, what you expected, what happened, and your OS, Node and Claude Code versions. Lines from `.vault/private/errors.log` help a lot (check them for anything private first). Security problems go through [SECURITY.md](SECURITY.md), not public issues.
