1. In the current project, read `.vault/STATE.md`. If it doesn't exist, say so and ask what to continue. (The project's rules are already loaded: CLAUDE.md, .claude/rules and auto memory.)
2. Tell the user in two or three lines what you are picking up: the north star, the next action, the open items, and how old the packet is (its header has the time). If its **Where** names a worktree, work in that folder.
3. The **Mission contract** carries over from chat to chat. Its **Binding rules** are the user's own words: follow each one exactly, all of them, for the whole session (a [skill/workflow] rule means load and follow that skill with the Skill tool, not just read its files). Never propose or repeat anything under **Rejected**. If the mission says it is done, ask what is next instead. Its **Steps** are what the user asked for, item by item: when you finish one and its check passes, tick it with the command its Steps line gives (`node "${CLAUDE_PLUGIN_ROOT}/cortex/src/cli.ts" mission done <n> --mission <id>`; `mission add "<step>"` for one the list missed); never tick a step that isn't finished, and name the steps you ticked in your reply. **Pinned for this session** holds what the session set out to do, the user's standing instructions in their own words and the decisions recorded at handoff: treat them as binding unless the user changes them. If it lists **memory notes flagged, not fixed yet**, those notes were loaded with your memory but may be wrong: don't rely on them, and tell the user in one line. **Session trail** is what earlier turns did, so don't redo finished work. **Where we left off** holds the last exchanges word for word, oldest first. Treat the newest reply as your own previous message: if it was a plan, a table or a list of findings, you already have it, so don't redo the work. **Active files**, **Last check** and **Open items** say what is in progress. When you go on, continue from **Next action** (or the open items). A turn-specific instruction in an earlier user message, such as "don't edit yet", applied to that turn only.
4. What to do now. Words after /cortex-resume in the same message are the task: if they only ask something, answer from the packet and don't edit anything. With /cortex-resume alone: if the packet's header says **HANDOFF READY** (a usage limit stopped the last chat mid-task), continue from **Next action** at once; otherwise end your two or three lines with the next action as one short question ("Start on …?") and wait for the user before you edit any file.
5. If the goal is marked as from an earlier session, check `git log -5 --oneline` and the working tree first: it may already be done. Then ask what to continue.
6. Don't read old transcripts or `.vault/private/` files: the packet is what carries over.
7. You are done only when the commands under **Verify** pass. Run them and report the output.
